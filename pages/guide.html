RELEASE DESK · 使用指南

开始检查之前

把每次 App 发布需要核对的配置、权限、订阅商品和检查证据集中管理，检查完成后再归档本次发布。

数据保存与备份：请务必先读

  • 数据默认保存在当前设备、当前浏览器的网站存储中。这是 GitHub Pages 个人版，无需注册账号，也不会因打开网页就自动备份或同步。更换设备、浏览器或浏览器用户后，不会自动看到原记录。
  • 勾选不等于已保存。检查项修改后请点击“保存进度”或“保存全部”，并确认页面显示“已保存”。备注、权限、订阅和发布信息按各自界面的保存提示操作；保存失败时先保留页面和草稿，排查后重试。
  • 请保存并妥善保管加密密钥。首次使用可输入已有密钥或随机生成；锁定、解锁及加密备份恢复都需要对应密钥。密钥遗失后，本工具无法替你找回加密内容。备份与密钥建议分别保管。
  • 清理网站数据、卸载浏览器、重装系统或更换设备前，必须先备份。到首页“数据管理”导出全部项目与草稿，确认文件真正下载成功，再保留对应密钥。无痕窗口的数据可能在关闭后被清除，不适合长期使用。
  • 本机快照和回收站不等于离线备份。每项目最多保留 10 份历史快照；回收站可恢复移除的项目，但它们同样依赖当前浏览器数据，清理后也可能一起丢失。
  • 跨设备同步需要你手动操作。连接自己的私有 GitHub 仓库后，在原设备点击“上传本机数据”，在另一设备连接同一仓库后点击“拉取 GitHub 数据”。连接成功不代表已经上传，请核对同步结果及加密提示。
  • 导出内容可能包含项目配置、接口地址和证据。加密 JSON 恢复需要原密钥；Markdown、摘要等可读文件请按内容妥善保管。不要将敏感记录、密钥或 GitHub Token 分享给无关人员。

按这 5 步开始使用

  1. 创建或导入项目

    从首页“新建 / 导入项目”选择模板、发布平台和实际使用的功能、权限；也可导入 Markdown 或完整项目 JSON。已有源码工程首次接入时，点击“获取 AI 工程采集说明”，将说明交给可读取工程的 AI，核对生成的 Markdown 后再导入；其中的结构化发布信息、功能、权限和订阅会自动带入。订阅、Adjust、Firebase、AnalysisApi、已选权限及配置启用即必检；订阅与统计 SDK 同时启用时自动核对订阅事件。权限说明默认通用，特殊用途可编辑；未知项需人工确认。明文文件直接导入，加密 JSON 需填写该文件对应的密钥。

  2. 核对项目配置

    在详情页“项目配置”中维护项目设置、权限和订阅商品，在“发布”中填写版本、构建号、负责人及真实配置。启用某功能不代表配置完整；“配置已记录”也不代表已经真机验证。

  3. 逐项检查并保存

    按清单核实实际结果，完成后勾选；不适用的项目填写跳过原因，重要结论补充备注和证据。按保存提示确认落盘。功能或平台不适用的条目会隐藏，历史进度仍保留。

  4. 处理阻塞项，再归档发布

    顶部会列出待检查、缺失证据和配置问题。处理率包含跳过项，“100%”不代表全部验证通过，也不等于商店审核通过。发布前核对就绪检查，再在“发布”中归档本次结果；下一版本使用“开始新一轮发布”。

  5. 备份与恢复

    单个项目可从卡片“更多操作”导出，所有项目及草稿可从“数据管理”整体备份。完整工作台备份从“导入工作台备份”恢复；单项目 JSON 从“新建 / 导入项目”导入。导入前核对项目与变更预览。

更新配置、恢复与多人操作

  • 更新源码配置时，可在导入目标中选择已有项目，逐字段比较当前值与导入值，再更新所选配置；原检查进度、备注、证据和订阅商品保持不变。默认新建导入则会生成独立项目。
  • 误移除项目可到首页“回收站”恢复。历史快照恢复会回到对应的项目状态，请先核对时间和内容并备份当前数据。
  • 多个标签页或多台设备同时修改可能产生冲突。遇到版本变化提示时，先导出或保留草稿，再刷新、拉取并比较；不要反复覆盖保存。
  • 每个项目都需要单独确认阅读说明。取消确认会重新锁定检查入口，但保留已有检查进度。
