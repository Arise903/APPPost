连接私有 GitHub 数据仓库

选择你有权限访问的私有仓库；无需使用指定名称。

1 准备私有仓库

仓库用来保存你的项目备份。如果已经有私有仓库，直接填写下方信息。

去 GitHub 创建仓库 ↗
  1. 选择你的账号或组织作为 Owner。
  2. Repository name 自行命名，例如 release-data。
  3. 可见性选择 Private，再点击 Create repository。空仓库也可连接。

例如仓库地址是 github.com/your-name/release-data：
所有者填 your-name，仓库名称填 release-data。不要把整个网址填入输入框。

填写后会显示本次连接的仓库。

2 创建访问令牌（Token）

Token 用于授权工作台访问这个仓库，不是 GitHub 登录密码。

去 GitHub 创建 Fine-grained Token ↗

链接会预填名称、30 天有效期和 Contents 权限；仍需在 GitHub 核对并选择目标仓库。

  1. Token name：例如 Release Desk sync；Expiration：选择有效期。
  2. Resource owner：选择 步骤 1 填写的所有者。
  3. Repository access → Only select repositories：只勾选 步骤 1 填写的仓库。
  4. 在 Permissions 中添加 Repository permissions → Contents → Read and write。不需要 Workflows 权限。
  5. 点击 Generate token，复制生成的完整 Token，回到这里粘贴。
查看 GitHub 官方 Token 配置说明 ↗

3 粘贴 Token 并验证

点击下方「验证并连接」。系统会检查仓库是否存在、是否为私有仓库，以及 Token 是否可以访问。

Token 仅保存在当前标签页会话，不进入备份或导出；本页面和同源脚本仍能访问它，请勿在共享设备连接。关闭标签页后需要重新输入。

连接失败时如何处理？
  • Token 无效 / 过期：检查是否完整复制，或重新生成 Token。
  • 仓库不存在 / 无权访问：核对步骤 1 的所有者和仓库名，以及步骤 2 的 Resource owner 和所选仓库。
  • 无法上传：核对 Contents 是否为 Read and write；连接成功只代表仓库可访问，不代表已经验证写入权限。
  • 组织仓库：如果 Token 显示 Pending，需等待组织管理员批准。
  • 公开仓库：请将数据仓库设为 Private 后重试。

连接后：首次备份点击「上传本机数据」；在另一设备恢复时点击「拉取 GitHub 数据」。连接本身不会自动上传。
